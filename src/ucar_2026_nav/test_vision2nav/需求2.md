# 视觉触发导航包需求
## 基本思路
整个过程分为巡航、导航到视觉触发点、导航到结束点。
巡航：先根据预先标点，依次巡航到目标点，每到下一个点判断可行性，不可行则跳过。
视觉触发：预留视觉接口，视觉检测到目标后打断当前导航，发送经过计算的目标点。
导航到结束点：根据预先标点（与视觉触发点不同），导航到结束点。
## 阶段一：巡航
- 输入：一组预先标的导航点：(9个点)
```bash
x   = -1.6499  y   = -1.7735  yaw = 1.0417 rad
x   = -1.6613  y   = -2.2796  yaw = -3.1404 rad
x   = -1.6846  y   = -2.7856  yaw = -3.1176 rad
x   = -0.6965  y   = -2.8239  yaw = -1.5594 rad

x   = 1.2660   y   = -2.8863  yaw = -1.5443 rad
x   = 2.3356   y   = -2.7417  yaw = -2.1786 rad
x   = 2.3471   y   = -1.6090  yaw = -0.8607 rad
x   = 1.2641   y   = -1.6452  yaw = 0.8530 rad

x   = 0.3011   y   = -1.6319  yaw = 0.8913 rad
```
- 因为导航costmap的更新有距离限制，所以导航运行过程中需要不断通过定时器判断当前目标点是否可行
- 判断是否可行：查costmap的代价，设置一个阈值参数（可yaml外部传入或其他文件外部传入），如果代价大于阈值，认为不可行，然后直接跳到下一个点
- 每次导航到当前点完成后，需要进行一个小范围的自转运动（发送wz控制命令，大小设为参数，所有点公用这一个速度（可yaml外部传入或其他文件外部传入）），速度设置之后需要自转保持一段时间，每个点都不一样，需要参数传入，具体怎么实现看你。直接通过与导航发速度相同的话题发布，控制指令如下
- 自转完成后可以发送下一个点
```bash
x   = -1.6499  y   = -1.7735  yaw = 1.0417 rad  ： 左自转，保持时间：1.5秒
x   = -1.6613  y   = -2.2796  yaw = -3.1404 rad ： 先右自转，保持时间：0.5秒，再左自转，保持时间：0.5秒
x   = -1.6846  y   = -2.7856  yaw = -3.1176 rad ： 左自转，保持时间：2秒
x   = -0.6965  y   = -2.8239  yaw = -1.5594 rad ： 先右自转，保持时间：0.5秒，再左自转，保持时间：0.5秒

x   = 1.2660   y   = -2.8863  yaw = -1.5443 rad ： 先右自转，保持时间：1秒，再左自转，保持时间：0.5秒
x   = 2.3356   y   = -2.7417  yaw = -2.1786 rad ： 左自转，保持时间：2.5秒
x   = 2.3471   y   = -1.6090  yaw = -0.8607 rad ： 左自转，保持时间：2.5秒
x   = 1.2641   y   = -1.6452  yaw = 0.8530 rad  ： 左自转，保持时间：1.5秒

x   = 0.3011   y   = -1.6319  yaw = 0.8913 rad ： 左自转，保持时间：1.5秒
```

## 阶段二：视觉触发
长方形四个直角点：手标有一定误差，忽略即可
```bash
x   = -2.2311  y   = -1.2505
x   = 2.8000  y   = -1.1940
x   = -2.2197 y   = -3.2746
x   = 2.7739 y   = -3.2186
```
- 你可以查看base_driver和TF相关代码，找有没有摄像头TF信息，如果有，这就是车头朝向
- 安全距离是d是0.4米，保持车头朝向与交点墙面垂直，也就是你说的向内法向量
