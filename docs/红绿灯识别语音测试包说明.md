# 红绿灯识别语音测试包说明

本文档总结本次新增的红绿灯识别语音测试链路，以及车上测试时的启动、诊断和排查方法。

## 1. 本次任务做了什么

新增测试包：

```text
src/ucar_2026_traffic_light_speak_test/
├── CMakeLists.txt
├── package.xml
├── launch/
│   └── traffic_light_speak_test.launch
└── scripts/
    ├── traffic_light_speak_test_node.py
    └── check_traffic_light_test.py
```

这个包不重新训练模型，也不重写 YOLO 推理。它复用现有 `yolo` 包里的：

- `traffic_light_inference_node.py`
- `config/traffic_light.yaml`
- `models/best.pt`

新包主要负责两件事：

1. 一键启动摄像头、YOLO 推理、TTS、debug 画面查看器和语音桥。
2. 订阅 `/traffic_light/detections`，读取 YOLO 的稳定共识结果 `consensus`，然后向 `/speak` 发布中文播报。

另外，本次也改了 `src/yolo/traffic_light_inference_node.py` 的模型加载逻辑：

- 优先使用本地 YOLOv5 repo。
- 默认会查找 `/home/ucar/yolov5`。
- 如果找不到本地 repo，才回退到 `torch.hub.load("ultralytics/yolov5")`。
- 这样适配车上离线环境，避免因为没有网络或 torch hub 缓存导致推理节点启动即退出。

## 2. 语音播报逻辑

语音桥节点：

```bash
rosrun ucar_2026_traffic_light_speak_test traffic_light_speak_test_node.py
```

默认订阅：

```text
/traffic_light/detections
```

默认发布：

```text
/speak
```

它只读取 JSON 里的 `consensus` 字段：

```json
{
  "consensus": {
    "class_name": "red_light",
    "active": true,
    "confidence": 0.85,
    "held_frames": 6
  }
}
```

播报映射如下：

| YOLO 类别 | 播报文本 |
|---|---|
| `red_light` | 识别到红灯，请停车等待。 |
| `green_straight` | 识别到绿灯直行，请直行。 |
| `green_left` | 识别到绿灯左转，请左转。 |
| `green_right` | 识别到绿灯右转，请右转。 |

默认策略是“变化播报”：

- 第一次稳定识别到某个类别会播报。
- 后续如果还是同一个类别，不重复播报。
- 类别变化后再次播报。
- `consensus.active=false` 时不播报。

语音桥状态话题：

```bash
rostopic echo /traffic_light_speak_test/status
```

常见状态：

| 状态 | 含义 |
|---|---|
| `waiting` | 节点已启动，等待检测消息 |
| `speaking:red_light` | 正在播报红灯 |
| `ignored:inactive` | YOLO 没有稳定共识 |
| `ignored:same_class:<class>` | 类别未变化，所以不重复播报 |
| `ignored:bad_json` | 检测消息不是合法 JSON |

## 3. 一键启动方式

车上先 source 两个工作空间：

```bash
source ~/ucar_ws/devel/setup.bash
source ~/2026-xunfei-race/devel/setup.bash
```

首次修改后编译：

```bash
cd ~/2026-xunfei-race
catkin_make --pkg yolo ucar_2026_traffic_light_speak_test
source devel/setup.bash
```

推荐启动：

```bash
roslaunch ucar_2026_traffic_light_speak_test traffic_light_speak_test.launch \
  flip:=true \
  yolov5_repo_path:=/home/ucar/yolov5
```

`/home/ucar/yolov5` 必须是 YOLOv5 源码目录，里面应有：

```text
/home/ucar/yolov5/hubconf.py
```

launch 默认启动组件：

| 组件 | 作用 |
|---|---|
| `usb_cam` | 发布 `/usb_cam/image_raw` |
| `traffic_light_inference_node.py` | YOLO 红绿灯推理 |
| `voice_speak_node` | 订阅 `/speak` 并语音播报 |
| `traffic_light_speak_test_node.py` | 检测结果转语音 |
| `image_view` | 查看 `/traffic_light/debug_image` |
| `audio_setup_node.py` | 设置 ALSA 音量 |

常用 launch 参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `flip` | `true` | 水平翻转图像，纠正小车摄像头镜像 |
| `yolov5_repo_path` | 空 | 本地 YOLOv5 repo 路径 |
| `start_camera` | `true` | 是否启动 usb_cam |
| `start_inference` | `true` | 是否启动 YOLO 推理 |
| `start_tts` | `true` | 是否启动 TTS |
| `start_viewer` | `true` | 是否启动 debug 图像窗口 |
| `repeat_same` | `false` | 是否重复播报同一类别 |
| `min_interval_sec` | `1.5` | 两次播报最小间隔 |
| `inference_required` | `false` | 推理节点死亡时是否关闭整个 launch |

如果已经单独启动摄像头：

```bash
roslaunch ucar_2026_traffic_light_speak_test traffic_light_speak_test.launch \
  start_camera:=false \
  flip:=true \
  yolov5_repo_path:=/home/ucar/yolov5
```

如果只想测试语音桥，不启动 YOLO：

```bash
roslaunch ucar_2026_traffic_light_speak_test traffic_light_speak_test.launch \
  start_camera:=false \
  start_inference:=false \
  start_viewer:=false
```

然后手动发一条检测消息：

```bash
rostopic pub -1 /traffic_light/detections std_msgs/String \
'{"data":"{\"consensus\":{\"class_name\":\"red_light\",\"active\":true,\"confidence\":0.9,\"held_frames\":6}}"}'
```

预期会播报：

```text
识别到红灯，请停车等待。
```

## 4. 诊断脚本

新增诊断脚本：

```bash
rosrun ucar_2026_traffic_light_speak_test check_traffic_light_test.py
```

它会检查：

- `yolo` 包是否能被 `rospack` 找到。
- `yolo/models/best.pt` 是否存在。
- 本地 YOLOv5 repo 是否存在。
- `traffic_light_inference` 节点是否运行。
- `voice_speak_node` 是否运行。
- `/usb_cam/image_raw`、`/traffic_light/detections`、`/traffic_light/status`、`/speak` 是否存在。
- 是否能读到 `/traffic_light/status` 和 `/traffic_light/detections` 的样本。

如果输出：

```text
[WARN] local yolov5 repo not found
```

说明没有找到本地 YOLOv5 源码。当前车上已配置 `/home/ucar/yolov5`，这项应为 OK。

## 5. 识别不出来时怎么排查

现在你遇到的是：推理节点不再崩，但测试一分多钟没有识别结果。这个问题要分两层看：

1. YOLO 是否完全没有框。
2. YOLO 有 raw 框，但没有达到 `consensus` 稳定共识。

### 5.1 先看节点是否活着

```bash
rosnode list | grep traffic_light_inference
rostopic echo /traffic_light/status -n1
```

期望状态：

```text
tracking
```

### 5.2 看检测话题是否在发布

```bash
rostopic hz /traffic_light/detections -w5
```

期望有接近配置的频率，默认约 10Hz。CPU 模式可能更低。

### 5.3 看 raw_detections

```bash
rostopic echo /traffic_light/detections -n1
```

重点看：

```json
"raw_detections": []
```

如果一直是空数组，说明模型完全没检出红绿灯。优先排查：

- 红绿灯是否在画面里。
- `flip:=true` 是否正确。可以试 `flip:=false` 对比。
- 光照、距离、角度是否和训练数据差异太大。
- 模型权重是否就是红绿灯权重：`yolo/models/best.pt`。
- 置信度阈值是否过高。

可以临时降低阈值测试：

```bash
roslaunch ucar_2026_traffic_light_speak_test traffic_light_speak_test.launch \
  flip:=true \
  yolov5_repo_path:=/home/ucar/yolov5 \
  start_viewer:=true
```

然后修改 `src/yolo/config/traffic_light.yaml`：

```yaml
confidence_threshold: 0.25
consensus_confirm_frames: 2
```

改完需要重启 launch。

### 5.4 看 consensus

如果 `raw_detections` 有内容，但：

```json
"consensus": {
  "active": false
}
```

说明 YOLO 有瞬时检测，但没有连续稳定到达 `consensus_confirm_frames`。

可临时调低：

```yaml
consensus_confirm_frames: 2
consensus_release_frames: 5
consensus_timeout: 2.0
```

这会更容易播报，但也更容易误报。测试阶段可以先这样确认链路。

### 5.5 看 debug 图像

一键启动默认打开：

```text
/traffic_light/debug_image
```

如果 X11 窗口不可用，可以用：

```bash
rosrun image_view image_view image:=/traffic_light/debug_image
```

看画面左上角：

```text
TL: none
```

表示没有共识。

如果有框但类别不对，说明模型分类不稳定，需要补充训练数据或检查类别顺序。

### 5.6 单独测 YOLO，不测语音

为了排除语音桥干扰：

```bash
roslaunch yolo traffic_light_inference.launch \
  flip:=true \
  yolov5_repo_path:=/home/ucar/yolov5
```

然后看：

```bash
rostopic echo /traffic_light/detections -n5
```

如果这里都没有检测，问题在 YOLO/模型/画面，不在语音测试包。

## 6. 当前最可能的问题

结合现象“环境配好了，测试一分多钟也识别不出来”，最可能不是语音包问题，而是 YOLO 输出没有稳定共识。

按优先级排查：

1. `rostopic echo /traffic_light/detections -n1` 看 `raw_detections` 是否为空。
2. 如果 raw 为空，先试 `flip:=false`。
3. 如果 raw 仍为空，把 `confidence_threshold` 降到 `0.25`。
4. 如果 raw 有框但 consensus inactive，把 `consensus_confirm_frames` 降到 `2`。
5. 如果类别错，检查训练类别顺序是否与代码一致：

```python
["green_left", "green_right", "green_straight", "red_light"]
```

类别顺序不一致时，即使检测到了，播报也会错。
