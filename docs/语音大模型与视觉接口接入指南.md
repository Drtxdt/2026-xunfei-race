# 语音大模型与视觉接口接入指南

本文档给任务联调同学使用，说明如何在正式业务节点中接入语音大模型、语音播报和视觉二维码接口。

注意：不要依赖 `ucar_2026_qr_speak_test` 测试包。那个包只用于临时验证摄像头、二维码和播报链路，正式任务应直接调用本文档中的 ROS topic、service 和 yolo 包脚本。

## 1. 工作空间准备

小车上有两个 ROS 工作空间，建议每个终端都按顺序执行：

```bash
source ~/ucar_ws/devel/setup.bash
source ~/2026-xunfei-race/devel/setup.bash
```

修改代码或新增节点后，在比赛工作空间根目录编译：

```bash
cd ~/2026-xunfei-race
catkin_make
source devel/setup.bash
```

## 2. 语音播报接口

语音合成节点订阅 `/speak`。

| 项目 | 值 |
|---|---|
| Topic | `/speak` |
| 类型 | `std_msgs/String` |
| 作用 | 把文本转成小车语音播报 |

启动语音合成节点：

```bash
cd /home/ucar/ucar_ws/src/speech_command/bin
source /home/ucar/ucar_ws/devel/setup.bash
rosrun speech_command voice_speak_node
```

命令行测试：

```bash
rostopic pub -1 /speak std_msgs/String "data: '取得香蕉属于食品大类应放置在食品加工车间'"
```

Python 调用示例：

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-

import rospy
from std_msgs.msg import String


def main():
    rospy.init_node("example_speak_client")
    pub = rospy.Publisher("/speak", String, queue_size=1)
    rospy.sleep(1.0)
    pub.publish(String(data="取得香蕉属于食品大类应放置在食品加工车间"))


if __name__ == "__main__":
    main()
```

比赛要求的完整播报格式：

```text
取得[货品名称]属于[目标大类]应放置在[目标仓库]，仿真环境中取得[货品名称]属于[目标大类]应放置在[目标仓库]
```

示例：

```text
取得香蕉属于食品大类应放置在食品加工车间，仿真环境中取得毛巾属于日用品大类应放置在日用品加工车间
```

## 3. 大模型推理接口

大模型模块把“三个二维码物品名 + 语音指令”推理成最终领取物品、目标大类、目标车间和播报文本。

启动服务：

```bash
source ~/ucar_ws/devel/setup.bash
source ~/2026-xunfei-race/devel/setup.bash
roslaunch ucar_2026_smart_factory_llm reason_pickup.launch
```

服务信息：

| 项目 | 值 |
|---|---|
| Service | `/smart_factory_llm/reason_pickup_order` |
| 类型 | `ucar_2026_smart_factory_llm/ReasonPickupOrder` |

查看接口定义：

```bash
rossrv show ucar_2026_smart_factory_llm/ReasonPickupOrder
```

输入字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `item_a` | string | 第一个二维码稳定识别出的物品名 |
| `item_b` | string | 第二个二维码稳定识别出的物品名 |
| `item_c` | string | 第三个二维码稳定识别出的物品名 |
| `voice_instruction` | string | 语音识别得到的完整任务指令 |

返回字段中，正式任务通常只需要这些：

| 字段 | 说明 |
|---|---|
| `success` | 是否推理成功 |
| `pickup_item` | 物品领取区要取得的货品 |
| `pickup_major` | 物品领取区货品所属大类 |
| `pickup_workshop` | 物品领取区货品应放置车间 |
| `sim_item` | 仿真环境中要取得的货品 |
| `sim_major` | 仿真环境货品所属大类 |
| `sim_workshop` | 仿真环境货品应放置车间 |
| `announcement_full` | 可直接发给 `/speak` 的完整播报文本 |

命令行调用示例：

```bash
rosservice call /smart_factory_llm/reason_pickup_order \
"{item_a: '香蕉', item_b: '毛巾', item_c: '手机', voice_instruction: '小飞小飞，前往物品领取区，取得食品类，放置在对应仓库，并领取仿真环境中需要的日用品类放置在对应仓库'}"
```

Python 调用示例：

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-

import rospy
from std_msgs.msg import String
from ucar_2026_smart_factory_llm.srv import ReasonPickupOrder


def main():
    rospy.init_node("example_reason_and_speak")
    rospy.wait_for_service("/smart_factory_llm/reason_pickup_order")
    reason = rospy.ServiceProxy(
        "/smart_factory_llm/reason_pickup_order",
        ReasonPickupOrder,
    )
    speak_pub = rospy.Publisher("/speak", String, queue_size=1)
    rospy.sleep(1.0)

    resp = reason(
        item_a="香蕉",
        item_b="毛巾",
        item_c="手机",
        voice_instruction="小飞小飞，前往物品领取区，取得食品类，放置在对应仓库，并领取仿真环境中需要的日用品类放置在对应仓库",
    )

    if not resp.success:
        rospy.logerr("reason failed: %s", resp.error_message)
        return

    rospy.loginfo("pickup=%s workshop=%s", resp.pickup_item, resp.pickup_workshop)
    rospy.loginfo("simulation=%s workshop=%s", resp.sim_item, resp.sim_workshop)
    speak_pub.publish(String(data=resp.announcement_full))


if __name__ == "__main__":
    main()
```

## 4. 视觉二维码接口

二维码识别由 `yolo` 包提供，正式节点不需要使用测试包。

启动摄像头后运行二维码识别：

```bash
source ~/ucar_ws/devel/setup.bash
source ~/2026-xunfei-race/devel/setup.bash
rosrun yolo qr_collect_and_decode.py --topic /usb_cam/image_raw --pub-topic /qr_code_data --fetch
```

如果摄像头画面左右镜像，增加 `--flip`：

```bash
rosrun yolo qr_collect_and_decode.py --topic /usb_cam/image_raw --pub-topic /qr_code_data --fetch --flip
```

二维码输出话题：

| 项目 | 值 |
|---|---|
| Topic | `/qr_code_data` |
| 类型 | `std_msgs/String` |
| 内容 | JSON 字符串 |

输出示例：

```json
{
  "stamp": 1780744663.397723,
  "count": 1,
  "items": [
    {
      "raw": "http://49.232.30.203:5000/flow2/daily",
      "api": {"code": 200, "result": "毛巾"},
      "ok": true,
      "result": "毛巾",
      "error": null
    }
  ]
}
```

业务节点只需要取 `items[*].result`。不要把二维码链接、状态码或完整 JSON 传给大模型。

正确传递：

```text
毛巾
```

错误传递：

```text
{"code":200,"result":"毛巾"}
http://49.232.30.203:5000/flow2/daily
```

## 5. 二维码结果锁定策略

比赛中三个二维码位置随机，且链接可能随机返回对应大类的子类。正式逻辑建议：

1. 看到一个新的二维码链接后，只请求并锁定一次 `result`。
2. 同一个二维码不要每帧重复调用接口。
3. 等三个不同二维码都拿到稳定物品名后，再调用大模型。
4. 如果某个二维码接口临时失败，可以保留原始链接并重试，但不要用失败状态码参与推理。

推荐内部结构：

```python
qr_results = {
    "http://.../food": "香蕉",
    "http://.../daily": "毛巾",
    "http://.../electronic": "手机",
}
```

然后传给大模型：

```python
items = list(qr_results.values())
resp = reason(
    item_a=items[0],
    item_b=items[1],
    item_c=items[2],
    voice_instruction=voice_text,
)
```

## 6. 视觉摄像头接口

USB 摄像头图像话题：

| Topic | 类型 | 说明 |
|---|---|---|
| `/usb_cam/image_raw` | `sensor_msgs/Image` | 原始摄像头画面 |

检查摄像头是否有数据：

```bash
rostopic hz /usb_cam/image_raw
```

查看图像：

```bash
rosrun image_view image_view image:=/usb_cam/image_raw
```

如果使用 MobaXterm，需要先打开 X11 转发，再 SSH 到小车后启动 `image_view`。

浏览器查看视频流可使用 `yolo` 包的 MJPEG 服务：

```bash
rosrun yolo camera_mjpeg_server.py
```

电脑浏览器打开：

```text
http://小车IP:8080/stream
```

## 7. 推荐正式联调流程

1. 启动底盘、摄像头和必要驱动。
2. 启动 `voice_speak_node`，确认 `/speak` 能播报。
3. 启动大模型服务 `reason_pickup.launch`。
4. 启动二维码识别 `rosrun yolo qr_collect_and_decode.py --fetch`。
5. 业务节点订阅 `/qr_code_data`，锁定三个 `result`。
6. 业务节点拿到语音识别文本 `voice_instruction`。
7. 业务节点调用 `/smart_factory_llm/reason_pickup_order`。
8. `success=True` 后，把 `announcement_full` 发布到 `/speak`。
9. 播报完成后，导航继续执行后续任务。

## 8. 常见问题

### 8.1 大模型服务找不到

先确认已编译并 source：

```bash
cd ~/2026-xunfei-race
catkin_make
source devel/setup.bash
rosservice list | grep reason_pickup_order
```

### 8.2 二维码能扫到，但没有物品名

检查是否加了 `--fetch`。不加 `--fetch` 时只能拿到二维码链接，拿不到接口返回的 `result`。

### 8.3 接口返回失败

如果 JSON 中出现：

```json
{"code": 400, "result": null}
```

或网络错误，说明二维码后端接口当前不可用。正式节点应重试或走赛前约定的兜底策略，但不要把错误码播报出来。

### 8.4 播报没声音

检查 `/speak` 是否有订阅者：

```bash
rostopic info /speak
```

正常应看到 `voice_speak_node`。如果没有，重新启动语音合成节点。

### 8.5 语音播报内容不符合赛规

不要自己拼错车间名。大类和车间只能使用：

| 大类 | 车间 |
|---|---|
| 食品大类 | 食品加工车间 |
| 日用品大类 | 日用品加工车间 |
| 电子产品大类 | 电子产品生产车间 |

最稳的做法是直接使用大模型服务返回的 `announcement_full`。
